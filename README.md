# Lassistant — Помощник юриста

**Версия приложения: 1.6.6.2**

Публичный снимок для ознакомления. Карточки в `config/executors.json` вымышленные: организации, счета, лицензии и имена директоров не существуют. Рабочие реквизиты в этот репозиторий не входят.

Локальное Windows-приложение для юристов: извлечение реквизитов из договоров, анонимизация персональных данных и генерация документов Word по шаблонам.

Помощник юриста помогает соблюдать Федеральный закон № 152-ФЗ «О персональных данных»: документы обрабатываются **на вашей стороне**, без передачи ПДн во внешние облака и API.

## Развёртывание (on-premises)

Это программное обеспечение устанавливается и работает на собственных серверах и оборудовании вашей компании, внутри вашего частного дата-центра (контура). Обработка документов выполняется **полностью локально**, без внешних API — требования конфиденциальности, 152-ФЗ, коммерческая тайна.

## Возможности

- **Создание документов** — каталог шаблонов (тип документа × клиент × услуга), подстановка `{{плейсхолдеров}}`, карточки заказчика
- **Найти сведения** — на вкладках «Шаблоны» и «Анонимизация» локальная модель находит в договоре стороны, объект, цену, сроки и реквизиты. Файл не уходит в интернет. Двойной щелчок по колонке «Контекст» открывает весь текст договора с подсветкой фрагмента
- **Анонимизация** — замена найденных сведений на плейсхолдеры `{{роль}}` и файл mapping для обратной подстановки
- **Шаблоны** — те же сведения сохраняются как шаблон `{{роль}}`, в том числе из цветных выделений в Word. Исправленный фрагмент может продолжаться в соседнем абзаце
- **Настройки** — каталог модели (`ner_model_1.0` / `ner_model_1.1`), минимальная уверенность и автопринятие по уверенности

## NER-модель для извлечения ролевых атрибутов (v1.1.1)

**Название:** NER-модель для извлечения ролевых атрибутов.

On-premises модель для юридических документов: находит в тексте договора **ролевые атрибуты** (реквизиты сторон, объекта, сумм, дат и т.п.), а не общие типы сущностей. Результат используется для анонимизации ПДн и заполнения / генерации шаблонов Word.

### Чем отличается от классического NER

Обычный NER даёт общие типы (`PER`, `ORG`, `MONEY`, `DATE`).

Здесь задача ближе к **slot filling / template extraction**: нужны **ролевые классы**, привязанные к структуре договора —

- не просто «это ФИО», а «ФИО Исполнителя» / «ФИО Заказчика»;
- не просто «это сумма», а «сумма договора».

После извлечения — отдельный шаг: найденные фрагменты (span) заменяются на плейсхолдеры шаблона (`{{исполнитель_…}}`, `{{заказчик_…}}`, даты, суммы и т.п.) и/или маркеры анонимизации.

С 1.6.6 в таблицах реквизитов сторона (Исполнитель / Заказчик) берётся из заголовка колонки и главнее стороны, которую предсказала модель. На 100 синтетических договорах ошибок стороны в таблицах стало 20 из 3 909 вместо 544 (весов модели это не меняет). Если у таблицы нет заголовков сторон, прежнее поведение сохраняется.

С 1.6.6.2 сторона определяется и в нестандартных таблицах: строка «Заказчики» / «ИСПОЛНИТЕЛЬ:» на всю ширину задаёт сторону ячеек ниже (договоры с несколькими заказчиками), вложенная таблица без заголовка берёт сторону своей ячейки. Вне таблиц части преамбулы получают сторону по словам «именуемое в дальнейшем «…»» (Заказчик может стоять первым), сторона из преамбулы больше не тянется на весь договор, подписи под строкой «Исполнитель   Заказчик» делятся по месту. На 20 синтетических договорах с пятью заказчиками ошибок стороны в таблицах стало 60 из 2 156 вместо 1 179.

Known issue до v1.2: party-путаница по ОГРН/КПП/ОКПО/ОКВЭД вне таблиц с заголовками сторон; если в договоре есть вторая таблица реквизитов без заголовков, в списке находок появляются пары `заказчик_…` / `исполнитель_…` с одинаковым текстом.

## Требования

- Windows 10 (1809+) / Windows 11, x64
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) — для сборки
- Python 3.11/3.12 — для Contract NER (см. установку ниже)

## Сборка

```bat
scripts\publish.bat
```

Результат: `publish\win-x64\Lassistant.exe`

Установка NER и Python-окружения: [docs/руководства/INSTALL_v1.6.6.2.md](docs/руководства/INSTALL_v1.6.6.2.md) (venv, путь модели — `ner_model_1.1`).

## Структура репозитория

```
src/                 исходники (.NET / WPF): App, Core, Extractors, Templates
config/              каталог документов, исполнители, contract-ner.json
templates/           шаблоны DOCX для поставки
scripts/             publish, release, contract_ner
docs/                инструкции и описания (CHANGELOG, руководства, роли NER)
models/              веса Contract NER (в git / LFS)
user/                личные данные и настройки — создаётся при первом запуске, не в git
```

В git **не** входят: `release/`, `publish/`, `python-venv-contract-ner/`, `user/`, артефакты `bin/` / `obj/`, `tz/` — полный список в [.gitignore](.gitignore).

Подробное описание слоёв, потоков данных и архитектурных решений — в [ARCHITECTURE.md](ARCHITECTURE.md).
