## 1.6.6.2 — 21.10.2026

**Релиз:** сторона по строкам-заголовкам («Заказчики» / «ИСПОЛНИТЕЛЬ:») и во вложенных таблицах; преамбула без «липкой» стороны.

### NER

- Строка на всю ширину с заголовком стороны задаёт сторону всех ячеек ниже — договоры с несколькими заказчиками. На 20 синтетических договорах с пятью заказчиками ошибок стороны в таблицах 60 из 2 156 вместо 1 179
- Вложенная таблица без заголовка берёт сторону ячейки родителя
- Заголовки «Заказчики» / «Исполнители» распознаются
- Преамбула: сторона части — по «именуемое в дальнейшем «…»»; сторона не тянется на весь договор после преамбулы; подписи под «Исполнитель   Заказчик» делятся по месту
- На 100 обычных синтетических договорах роли модели не изменились

### Известные проблемы

- Вторая таблица реквизитов без заголовков: пары `заказчик_…` / `исполнитель_…` с одинаковым текстом

### Прочее

- Номер версии в четырёх местах, включая `AppInfo` (окно «О программе»); правило `read-release-version.mdc`
- `AppInfo` / сборка: **1.6.6.2**
- Описание релиза: `docs/realese_history/RELEASE_v1.6.6.2.md`

### Новые возможности

- Кнопка **«Анонимизировать для LLM»**: сохраняет `_for_llm.txt` и `_for_llm.docx` с тегами `[FIELD:]` / `[EXEC:]` и вымышленными данными
- Кнопка **«Анализ LLM»**: автоматический запрос к OpenAI-совместимому API или Anthropic Claude (запасной путь)
- Сохранение отладочных файлов `_llm_request.txt` и `_llm_response.txt` рядом с документом
- Конфигурация LLM: `config/llm-settings.json` (провайдер, модель, API-ключ)
- Один цвет выделения для полей Заказчика; данные Исполнителя определяются автоматически

### Анонимизация для LLM

- `FieldAnonymizer` — замена реальных данных на вымышленные внутри тегов
- `AnonymizedDocxBuilder` — Word-копия с сохранением форматирования
- Единое фейковое ФИО и название организации Исполнителя по всему документу
- Тегирование реквизитов Исполнителя: ИНН, ОГРН, банк, адрес, email, телефон, ФИО

### Исправления

- Вложенные таблицы в приложении к договору (оборудование, цены) корректно попадают в текст для LLM

## 1.1.0 — 17.06.2026

**Релиз:** модуль анонимизации, стабилизация движка замены и расширение правил.

### Новые возможности

- Вкладка **«Анонимизация»** для `.docx` и `.pdf`
- Поиск ПДн по regex-правилам из `config/anonymization-rules.json` (19 категорий)
- Режимы поиска: **консервативный**, **агрессивный**, **только с подтверждением**
- Плейсхолдеры `[ФИО_1]`, `[ИНН_1]` и т.д. + файл `*.mapping.json` для восстановления
- Исключение «своих организаций» (`config/own-organizations.json`)
- Деанонимизация по mapping
- PDF: текстовый слой и OCR (Windows OCR) для сканов
- Проект `Lassistant.Anonymization` — отдельная сборка в solution

### Правила анонимизации (доработки)

- Категории **DATE**, **LICENSE**, **BANK**, **OBJECT**, **SNILS**
- Лицензирующий орган (Росгвардия, ФСВНГ)
- Орган выдачи паспорта (`Отделение милиции`, `ГУ МВД России`)
- Адреса: индекс, `обл.`, километр шоссе, участок ДНП
- Телефоны: `8 (XXX) XX-XX-XX`, `+7…`, контекст `телефон:`
- Email с кириллическими homoglyphs
- ФИО: подписи `/Иванов И.И./`, опечатки `Илья.Владимирович`
- Членские книжки садоводов, полное наименование ООО

### Исправления движка

- **Дедупликация пересечений:** приоритет High над Low (исправлен баг `OrderByDescending(Confidence)`)
- **Trim/offset:** корректные границы span после `Trim()`
- **DocxAnonymizer:** глобальная замена всех вхождений; сначала длинные фрагменты
- **TextNormalization:** NBSP, Unicode-маркеры направления (`\u202c`)
- **SNILS vs PHONE:** 11 цифр с `+7` / `телефон:` не классифицируются как СНИЛС
- Фильтр ложных ФИО (`т.п.`, `т.ч.`, `т.д.`)
- Исправление `NullReferenceException` при загрузке вкладки анонимизации
