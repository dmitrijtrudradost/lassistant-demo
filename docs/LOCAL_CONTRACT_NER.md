# Локальный Contract NER в Lassistant

| Параметр | Значение |
|----------|----------|
| Модуль | Contract NER (rubert-tiny2 + postprocess) |
| Где в UI | Вкладка **«Шаблоны»** → **«Найти сведения»** |
| ПДн | Обрабатываются только на этом ПК |

## Сценарий

1. Загрузите договор `.docx` (текст уже должен быть в файле; OCR — вне ПЮ, например FineReader).
2. Нажмите **«Найти сведения»**.
3. Проверьте таблицу ролей (уверенность, сторона), снимите галочки с лишнего, поправьте ключ при необходимости.
4. **«Сохранить шаблон»** — фрагменты заменяются на `{{роль}}` (например `{{заказчик_инн}}`).

### Обратная связь после ручной проверки

В таблице NER можно:

- снять галочку с ложной сущности;
- исправить роль/ключ;
- исправить границы через «Итоговый текст» — введённый текст должен дословно
  встречаться в показанном контексте;
- выделить фрагмент в колонке «Контекст» мышью и скопировать через `Ctrl+C`
  или контекстное меню (окно контекста — до 60 символов с каждой стороны);
- выбрать причину исправления и добавить комментарий.

При запуске NER локально сохраняется состояние `before`. После успешного
сохранения шаблона записываются `after` и список различий `corrections`.
Каталог находится рядом с приложением:

`feedback/contract-ner/<идентификатор-сеанса>/`

Внутри хранятся `metadata.json`, исходный NER-текст и fragments, `before.json`,
`after.json`, `corrections.json`, `completion.json`. Эти локальные данные не
отправляются автоматически и должны пройти проверку перед экспортом в
обучающий gold-набор.

### Режимы обработки

- **Рабочий (рекомендуется)** — NER + Python-постобработка + C#-агрегатор.
  Исправляет границы/стороны, удаляет мусор и дубли, оставляет лучшие значения ролей.
- **Диагностика: без C#-агрегатора** — NER + Python-постобработка.
  Показывает все вхождения после правил; дубли сохраняются.
- **Голая NER-модель** — без Python-постобработки и C#-агрегатора.
  Отсечение регулируется отдельным выбором уверенности; `0,00` показывает все сущности.

При смене режима прежние результаты очищаются; договор нужно разобрать заново.
Выбор сохраняется в `config/contract-ner.json`.

Перед запуском можно выбрать минимальную уверенность: от `0,00` (без отсечения) до
`0,90` (почти без сомнений). Порог применяется во всех трёх режимах. Тот же список в «Настройках» и на вкладке «Анонимизация».

В колонке «Роль / ключ» доступен список всех ролей модели; пункт
«— добавить новую —» позволяет ввести произвольный ключ плейсхолдера.

Для NER используется отдельное train-compatible извлечение DOCX: каждый абзац
ячейки таблицы передаётся отдельной строкой, ячейки разных сторон не склеиваются.
Структурные координаты таблицы передаются отдельно и не попадают в текст модели.
С 1.6.6 по ним определяется сторона колонки (по заголовку «ИСПОЛНИТЕЛЬ» / «ЗАКАЗЧИК»), и роль, найденная моделью в этой колонке, получает сторону колонки.
С 1.6.6.2 то же действует для строк-заголовков на всю ширину («Заказчики» над несколькими заказчиками, «ИСПОЛНИТЕЛЬ:» ниже) и для вложенных таблиц без заголовка; в преамбуле сторона части берётся из «именуемое в дальнейшем «…»» и не переносится на следующие абзацы.

Последний фактический вход можно проверить без отладчика:

- `diagnostics/contract-ner/input.txt`
- `diagnostics/contract-ner/input.fragments.json`

Каталог создаётся рядом с запущенным приложением.

## Установка модуля на Windows 11

Модель обучалась на Linux; для работы на Windows достаточно каталога весов и Python.

```bat
cd scripts\contract_ner
python -m venv ..\..\python-venv-contract-ner
..\..\python-venv-contract-ner\Scripts\pip install -r requirements-infer.txt
```

В поставке должны быть:

- `models/contract-ner/ner_model_final/` (веса + config + tokenizer + labels)
- `scripts/contract_ner/` (`inference_cli.py`, `postprocess.py`, …)
- `config/contract-ner.json`

Без модели кнопка покажет: «Модуль NER не установлен» — приложение не падает.

## Ограничения

- Тип: договоры **охраны**, заказчик = **ИП** (ООО/физлицо — после дообучения).
- Желательны заголовки секций **ИСПОЛНИТЕЛЬ** / **ЗАКАЗЧИК**.
- Ревью обязательно: на реальных текстах возможны обрезки банка/адреса.
- Метрика val ~0.97 F1 — ориентир, не гарантия на любом шаблоне.

## Что поставляется (не только веса)

Нужен весь каталог `ner_model_final/` + код `postprocess`/`inference_cli`.  
Не нужны: датасеты обучения, `train_ner.py`, Linux-окружение.

## Вкладка «Анонимизация»

Анонимизация через тот же NER-конвейер, что и «Шаблоны».

Сценарий: загрузить `.docx` → **Найти сведения** → проверить галочки/роли → **Анонимизировать** (результат в памяти) → **Сохранить** (`*_anon_ner.docx` + `*.mapping.json`) → при необходимости **Восстановить из mapping**.

Плейсхолдеры — `{{роль}}` (например `{{исполнитель_наименование}}`), как в «Шаблонах» (`NerSpanToTemplateConverter`). Mapping совместим с `DocxDeAnonymizer.Restore` (`Placeholder` ↔ `Original`).

## Конфиг

`config/contract-ner.json`:

- `min_score` — нижний порог показа сущностей в ревью (по умолчанию `0.05`)
- `auto_accept_score` — порог автоматической галочки; более слабые строки
  показываются жёлтым и требуют ручного подтверждения (по умолчанию `0.30`)
- `processing_mode` — `production`, `python_postprocess` или `raw`
- `python_path` — явный путь к `python.exe` (иначе автопоиск / venv)
