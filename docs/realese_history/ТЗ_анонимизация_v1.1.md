# Техническое задание: модуль анонимизации

**Продукт:** Помощник юриста (Lassistant)  
**Версия:** 1.1  
**Дата:** 17.06.2026  
**Статус:** Утверждённое ТЗ для разработки  

---

## 1. Назначение и цели

### 1.1. Назначение

Добавить в приложение «Помощник юриста» функцию **локальной анонимизации персональных и чувствительных данных** в юридических документах перед передачей в облачный ИИ, удалённую обработку или третьим лицам (подрядчики).

### 1.2. Цели v1.1

1. Обеспечить **обратимую** анонимизацию через плейсхолдеры (`[ФИО_1]`) и локальный JSON-mapping.
2. Поддержать форматы **`.docx`** и **`.pdf`** (включая сканы) на входе и **тот же формат** на выходе.
3. Реализовать **ручной контроль** списка найденных сущностей до применения замен.
4. Соблюдать принцип **локальной обработки** — данные не передаются в интернет в рамках работы модуля.
5. Заложить **расширяемую архитектуру** для подключения VLM/LLM в версиях 1.2+.

### 1.3. Вне scope v1.1

| Не входит в v1.1 | Планируемая версия |
|------------------|-------------------|
| Пакетная обработка папки | v1.1.1 |
| Английский язык документов | v1.2+ |
| PaddleOCR-VL и улучшенный OCR | v1.2 |
| Локальная LLM для поиска сущностей | v1.3 |
| Цветная разметка в Word | v1.2+ (опционально) |
| Редактор пользовательских regex в UI | v1.2+ |
| Связка с формой «Создать документ» | v1.2 |
| Внутренний регламент организации (полноценный UI) | v1.2+ (в v1.1 — задел в config) |

## 2. Пользователи и сценарии

### 2.1. Пользователи

- Юристы
- Секретари / бухгалтерия
- Внешние подрядчики (с тем же локальным приложением)

### 2.2. Основные сценарии

| ID | Сценарий | Описание |
|----|----------|----------|
| UC-01 | Анонимизация для ИИ | Юрист загружает договор → проверяет список сущностей → получает «чистый» файл + mapping локально → отправляет только анонимизированный файл в облачный ИИ |
| UC-02 | Анонимизация для подрядчика | То же, mapping хранится у юриста, подрядчику передаётся только анонимизированный документ |
| UC-03 | Деанонимизация | По запросу: анонимизированный файл + mapping → восстановление исходных данных |
| UC-04 | PDF-скан | Загрузка подписанного скана → OCR → поиск → замена → анонимизированный PDF + mapping |
| UC-05 | Исключение «свои организации» | Включён список «наших» юрлиц — они не попадают в замену |

### 2.3. Ограничение ответственности

Перед применением и перед отправкой в облако пользователь **обязан** просмотреть список сущностей. Приложение отображает дисклеймер: автоматический поиск не заменяет юридическую проверку; ответственность за передачу данных в облако несёт пользователь.

## 3. Функциональные требования

### 3.1. Интеграция в приложение

- Модуль размещается на **отдельной вкладке** «Анонимизация».
- Вкладка «Создать документ» в v1.1 **не изменяется** (кроме общей версии приложения 1.1).
- Обработка **одного файла за раз** (пакет — v1.1.1).

### 3.2. Поддерживаемые форматы

| Вход | Выход | Mapping |
|------|-------|---------|
| `.docx` | `.docx` (анонимизированный) | `имя.mapping.json` |
| `.pdf` (текстовый слой) | `.pdf` (анонимизированный) | `имя.mapping.json` |
| `.pdf` (скан / изображения страниц) | `.pdf` (анонимизированный) | `имя.mapping.json` |

**Соглашение об именах файлов (по умолчанию):**

- `договор.docx` → `договор_anon.docx` + `договор.mapping.json`
- `договор.pdf` → `договор_anon.pdf` + `договор.mapping.json`

Пути сохранения — через стандартный диалог «Сохранить как»; mapping предлагается сохранить **рядом** с результатом.

### 3.3. Категории данных для анонимизации

Все категории включаются/выключаются пользователем в UI (чекбоксы). Состав v1.1:

| Ключ | Категория | Примеры | Примечание |
|------|-----------|---------|------------|
| `PERSON` | ФИО | Иванов Иван Иванович | Низкая уверенность по умолчанию |
| `PASSPORT` | Паспортные данные | серия/номер, «кем выдан», код подразделения | Отдельная категория |
| `COMPANY` | Юрлица / контрагенты | ООО «Ромашка», ИП Петров | |
| `INN` | ИНН | 7707083893 | Высокая уверенность при валидной КС |
| `KPP` | КПП | 770701001 | |
| `OGRN` | ОГРН / ОГРНИП | 1027700132195 | |
| `BIK` | БИК | 044525225 | |
| `ACCOUNT` | Р/с, к/с | 40702810000000000001 | |
| `EMAIL` | Email | ivan@example.ru | |
| `PHONE` | Телефон | +7 (495) 123-45-67 | |
| `ADDRESS` | Адрес | г. Москва, ул. Лесная, д. 7 | Низкая уверенность по умолчанию |
| `CONTRACT` | Номер договора | № 123/АВ-2024 | Включено по требованию заказчика |
| `AMOUNT` | Суммы | 150 000 руб. | Включено по требованию заказчика |
| `URL` | URL / сайт | https://example.com | Опционально |

Язык документов в v1.1: **только русский (RU)**.

### 3.4. Режимы поиска

Пользователь выбирает один из трёх режимов:

| Режим | Описание | Поведение по умолчанию для галочек |
|-------|----------|-----------------------------------|
| **Агрессивный** | Широкие regex для ФИО, адресов, компаний | Больше кандидатов; низкая уверенность — часто вкл. |
| **Консервативный** *(рекомендуемый)* | Жёсткие шаблоны + валидаторы (ИНН, ОГРН, БИК, email, телефон, паспорт) | Высокая уверенность — вкл.; низкая — выкл. |
| **Только с подтверждением** | Ничего не заменяется без явной галочки | Все сущности — выкл. до клика пользователя |

### 3.5. Уровни уверенности

Каждая найденная сущность имеет уровень:

| Уровень | Критерии (примеры) | UI |
|---------|-------------------|-----|
| **Высокая** | ИНН/ОГРН/БИК с проверкой контрольной суммы; email; телефон по шаблону; паспорт `NN NN NNNNNN` | Зелёный индикатор |
| **Низкая** | ФИО без полного шаблона; адрес; название компании без маркера ООО/ИП; сомнительный OCR-текст | Жёлтый индикатор |

В консервативном режиме сущности с **низкой** уверенностью **не включаются** в замену без действия пользователя.

### 3.6. Режим замены

- **Единственный режим в v1.1:** плейсхолдеры в квадратных скобках.
- Формат: `[КАТЕГОРИЯ_N]`, например `[ФИО_1]`, `[ИНН_1]`, `[ПАСПОРТ_1]`.
- **Консистентность:** одно и то же значение в документе → один и тот же плейсхолдер.
- Счётчики ведутся **отдельно по категориям**.

Маскировка (`████`) и полное удаление — **не в v1.1** (возможны в v1.2).

### 3.7. Список «свои организации» (исключения)

| Требование | Описание |
|------------|----------|
| FR-EX-01 | Настраиваемый список организаций/ИНН «наших» сторон в config |
| FR-EX-02 | Переключатель **Вкл / Выкл** в UI |
| FR-EX-03 | При **Вкл** — совпадения не попадают в список замен ни в одном режиме |
| FR-EX-04 | При **Выкл** — обрабатываются по общим правилам |

Файл: `config/own-organizations.json` (см. раздел 6).

### 3.8. Экран проверки сущностей

Обязательные элементы:

1. Таблица/список: галочка | категория | фрагмент текста | плейсхолдер | уверенность | контекст (фрагмент абзаца).
2. Фильтр по категории и по уровню уверенности.
3. «Выбрать все» / «Снять все» / «Только высокая уверенность».
4. Кнопки: **«Анонимизировать»**, **«Отмена»**.
5. До нажатия «Анонимизировать» исходный файл **не изменяется**.

### 3.9. Mapping (JSON)

Для каждого обработанного файла создаётся отдельный mapping.

**Минимальная структура:**

```json
{
  "version": "1.0",
  "sourceFile": "договор.docx",
  "createdAt": "2026-06-17T12:00:00+03:00",
  "appVersion": "1.1.0",
  "searchMode": "conservative",
  "language": "ru",
  "replacements": [
    {
      "placeholder": "[ФИО_1]",
      "original": "Иванов Иван Иванович",
      "category": "PERSON",
      "confidence": "high"
    }
  ]
}
```

**Требования:**

- Mapping содержит **персональные данные** — при сохранении показывать предупреждение: не передавать вместе с «чистым» файлом в облако/ИИ.
- Кодировка UTF-8.
- При деанонимизации используется **только** пара файл + mapping той же сессии обработки.

### 3.10. Деанонимизация

| Формат | v1.1 |
|--------|------|
| `.docx` + mapping | **Обязательно** |
| `.pdf` + mapping | **Обязательно** (симметрично анонимизации PDF) |

UI: на вкладке «Анонимизация» подраздел или кнопка **«Восстановить (деанонимизация)»**:

1. Выбор анонимизированного файла.
2. Выбор соответствующего `.mapping.json`.
3. Предпросмотр количества замен.
4. Сохранение восстановленного файла (`_restored` в имени по умолчанию).

Замена выполняется по точному совпадению плейсхолдеров из mapping (с учётом консистентности).

### 3.11. PDF-сканы и OCR (v1.1)

| Этап | Реализация v1.1 |
|------|-----------------|
| Распознавание | **Windows.Media.Ocr** (существующий стек `PassportOcrExtractor`) |
| Предпросмотр | Показать распознанный текст (опционально, для PDF-сканов) |
| Замена в PDF | Redaction / перекрытие областей + текст плейсхолдера (техническая реализация на этапе проектирования) |

При низком качестве OCR — предупреждение пользователю; рекомендация режима «Только с подтверждением».

## 4. Нефункциональные требования

### 4.1. Безопасность и 152-ФЗ

- Обработка **локальная**; модуль анонимизации **не выполняет сетевых запросов**.
- Персональные данные **не логируются** в открытом виде.
- Ориентир по умолчанию — требования **152-ФЗ** (минимизация и обезличивание перед передачу третьим лицам).
- В config предусмотреть секцию `policy` для будущего внутреннего регламента организации (какие категории обязательны, текст дисклеймера).

### 4.2. Производительность

- Документ до ~50 страниц docx — обработка на типовом ПК без зависания UI (фоновый поток / async).
- Прогресс-бар для OCR PDF-сканов.

### 4.3. Реализация кода

- **Собственная реализация** на C# / .NET 8.
- Не копировать код LexAnon; допустимо использовать идеи категорий и подходы как референс.
- Для docx — **DocumentFormat.OpenXml** (как в `DocxTemplateEngine`).
- Для PDF — **PdfPig** (чтение) + выбранная библиотека записи/redaction.

### 4.4. Платформа

- Windows 10 (1809+) / Windows 11, x64.
- Русский языковой пакет OCR Windows.

## 5. Архитектура

### 5.1. Новый модуль

```
src/
├── Lassistant.Anonymization/     # NEW: ядро анонимизации
│   ├── Recognition/              # IDocumentRecognizer
│   ├── Detection/                # IEntityDetector, regex, validators
│   ├── Replacement/              # IReplacementEngine, mapping
│   ├── DeAnonymization/          # восстановление docx/pdf
│   └── Models/                   # EntityCandidate, AnonymizationSession
├── Lassistant.App/
│   ├── Views/AnonymizationView.xaml
│   └── ViewModels/AnonymizationViewModel.cs
└── ...
config/
├── anonymization-rules.json      # regex по категориям
├── anonymization-policy.json     # 152-ФЗ, дисклеймер, регламент (задел)
└── own-organizations.json        # свои организации
```

### 5.2. Три независимых слоя (обязательно для расширяемости)

```
[Вход] → IDocumentRecognizer → IEntityDetector → IReplacementEngine → [Выход + mapping]
```

| Интерфейс | Ответственность | v1.1 |
|-----------|----------------|------|
| `IDocumentRecognizer` | docx/pdf → унифицированный текст (+ spans с координатами для PDF) | DocxRecognizer, PdfTextRecognizer, WindowsOcrPdfRecognizer |
| `IEntityDetector` | Текст → список `EntityCandidate` с category, confidence, start, end | RegexEntityDetector |
| `IReplacementEngine` | Применение замен, генерация mapping | PlaceholderReplacementEngine |

### 5.3. Провайдеры (config)

`config/anonymization-providers.json`:

```json
{
  "recognition": {
    "default": "windows-ocr",
    "available": ["docx-native", "pdf-text", "windows-ocr"]
  },
  "detection": {
    "default": "regex-conservative",
    "available": ["regex-conservative", "regex-aggressive", "manual-only"]
  },
  "future": {
    "paddleocr-vl": { "enabled": false, "endpoint": "" },
    "local-llm": { "enabled": false, "endpoint": "" }
  }
}
```

## 8. Расширяемость: VLM и LLM (дорожная карта)

Архитектура v1.1 **не должна блокировать** подключение:

| Версия | Компонент | Назначение |
|--------|-----------|------------|
| **v1.2** | PaddleOCR-VL 0.9B (sidecar / ONNX) | Улучшенный OCR сканов, таблицы реквизитов, bbox для PDF redaction |
| **v1.3** | Локальная LLM | Поиск ФИО, адресов, компаний в контексте; кандидаты с низкой/высокой уверенностью |
| **v1.2+** | EN-правила | Англоязычные документы |

Новые движки подключаются как реализации `IDocumentRecognizer` / `IEntityDetector` без изменения формата mapping и UI-списка сущностей.

**Референс (не для копирования кода):** [LexAnon](https://github.com/LexProTech/LexAnon), [PaddleOCR-VL](https://huggingface.co/PaddlePaddle/PaddleOCR-VL).

## 9. Критерии приёмки v1.1

1. Вкладка «Анонимизация» открывается и обрабатывает один `.docx` → `_anon.docx` + `.mapping.json`.
2. Обрабатывается один `.pdf` с текстовым слоем → `_anon.pdf` + mapping.
3. Обрабатывается один `.pdf`-скан (Windows OCR) → `_anon.pdf` + mapping.
4. Деанонимизация восстанавливает исходный текст для docx и pdf при наличии корректного mapping.
5. Режим «Только с подтверждением» не меняет файл без явных галочек.
6. «Свои организации» (Вкл) — ни одна строка из списка не заменяется.
7. ИНН с неверной контрольной суммой **не** получает высокую уверенность.
8. Mapping не отправляется в сеть; дисклеймер отображается при сохранении mapping.
9. Сборка `publish.bat` копирует новые config-файлы в `publish\win-x64\config\`.
10. Версия приложения в «О программе» — **1.1**.

## 10. Риски и митигация

| Риск | Митигация |
|------|-----------|
| Ложные срабатывания regex | Консервативный режим по умолчанию; два уровня уверенности; ручной список |
| Пропуски в PDF-сканах | Предпросмотр OCR; предупреждение; v1.2 PaddleOCR-VL |
| Утечка через mapping | Предупреждение в UI; не включать mapping в пакет для ИИ |
| Сложность PDF redaction | Ранний прототип; docx — эталонный путь для приёмки |
| Деанонимизация PDF | Заложить в спринт 1; при блокере — эскалация (см. п. 11) |
